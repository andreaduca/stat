From a private key to a public key

A private key is a number k. The matching public key is the point Q = kG, reached by adding a fixed point G to itself k times on an elliptic curve. Going forward is cheap; going backward — recovering k from Q — is the hard problem the whole construction rests on. These pages do it on a curve small enough to see every point at once.

The exercise

Take the curve y² = x³ + 7 mod 17 and the base point G = (1,5). Choose a private key, say k = 6. Implement point addition, compute G, 2G, 3G, …, kG, and print the last one as the toy public key. Then do the same with the faster double-and-add method, and watch what changes when k, G or the curve changes.

The curve used here is y² = x³ + 7 — the same equation as secp256k1, the curve Bitcoin and Ethereum both sign with. What differs is the size. secp256k1 is taken modulo the 78-digit prime 2²⁵⁶ − 2³² − 977 and has roughly 10⁷⁷ points; here the modulus is 17 and the curve has 18 points, so a laptop can find the private key by simply trying all of them. The mathematics is the same in both cases — only the size separates a teaching aid from a system holding real money.

How to use these pages

  • The curve — see all the points at once, the symmetry that pairs P with −P, how many points there are, and the order of each one.
  • Key generation — the table of multiples G, 2G, 3G, …, the toy public key, the double-and-add trace, and the cost of each method side by side.
  • Visualiser — one group operation at a time, slowed down: the line through the two points, the third intersection, the reflection, and the arithmetic mod p that produced it.

Every panel has a “What am I looking at?” box, and the URL keeps your settings — keygen.html?curve=C1&k=6 — so a configuration can be bookmarked or linked.

Where this sits in a crypto wallet

Everything on these pages is step 2 of four. It is worth knowing which four.

  1. A private key is chosen — a random 256-bit number k. The 12 or 24 English words a wallet asks you to write down (a BIP-39 seed phrase) are a human-readable encoding of the seed that k is derived from. Those words are the key; nothing else is kept.
  2. The public key is computed as Q = kG on secp256k1. This is the operation these pages take apart, and the only step that is irreversible.
  3. An address is derived by hashing Q. Ethereum takes Keccak-256 of the 64-byte public key and keeps the last 20 bytes — that is the 0x… you paste. Bitcoin applies SHA-256 then RIPEMD-160 and encodes the result. Hashing here is about length and format, not secrecy: Q is public anyway.
  4. Spending requires a signature made with k (ECDSA), which proves the signer knows k without ever transmitting it.

A hardware wallet — a Ledger or a Trezor — exists to keep k inside a chip: it performs step 4 internally and emits only signatures, so the key never touches the computer. A software wallet holds k in the memory of a general-purpose machine, which is why a compromised laptop means compromised funds. Neither design would be worth building if step 2 could be run backwards.

What to try first

  1. On key generation, run k = 6 and check the table against your own hand computation.
  2. Push k past the order of G. The multiples start over: only k mod ord(G) ever mattered.
  3. Switch to curve C2 (modulus 1051) and compare the operation counters of the two methods as k grows. One grows like k, the other like log k.
  4. On the visualiser, step through a doubling and reproduce λ with pen and paper.
